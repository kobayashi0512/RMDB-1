# RMDB BiRAP V2 backbone candidate protocol (development only)

**Purpose.** Compare trainable occupancy backbones under one frozen RMDB BiRAP
identity, mass, and routing stack. This is a development experiment and is
not an outcome driven search.

## Prespecified candidates

* `baseline`: ResNet34 U-Net occupancy head, initialized from the existing FIVES
  checkpoint.
* `highres`: shallow high resolution skip path with three scale encoder and
  decoder, designed to preserve fine vessels.
* `global_local`: the same multi scale path with a learned global context gate
  at the bottleneck.
* `dualstream`: RGB path plus a fixed local contrast stream derived from the
  green channel; the fusion remains learnable.
* `direction`: RGB path augmented with the outcome blind Hessian orientation
  field already computed by the loader.

The candidate names are implementation labels until a result meets the
selection rule. No candidate is described as a new method before analysis.
The baseline starts from the existing FIVES checkpoint because it is the
published reference implementation; the four new heads are trained from
seeded random initialization. This initialization asymmetry is recorded and
will be disclosed with the results rather than hidden.

## Data and split

FIVES train images provide occupancy supervision (480 train, 120 validation);
the official FIVES test partition is untouched. RAV provides harmonised
artery, vein, crossing, and background labels (169 development train, 30
validation). The seven analogue camera cases are held out retrospectively and
are not used for selection. Fundus AVSeg, China Fundus CIMT, and mBRSET
outcomes are forbidden during this development run.

The split is generated by the existing `train_birap_v2.py` loader with seed
`20260906` and is written into each run directory. All candidates use the same
split, crop policy, optimizer, loss weights, and number of epochs.

## Training budget

* 12 epochs, AdamW, learning rate `5e-5`, weight decay `1e-4`.
* Training crop selected from 384, 512, 640, and 768 pixels; evaluation at
  768 pixels; batch size 2; zero data-loader workers for reproducibility.
* Full `variant=full` losses are used for every candidate. The only changed
  component is the occupancy backbone. The frozen VascX logits and frozen mass
  corrector are identical across candidates.
* Seeds: `20260906`, `20260907`, and `20260908`. A seed is complete only when
  `summary.json`, `best.pt`, validation CSVs, and a finite loss history exist.

## Endpoints and selection

Primary endpoint: mean RAV artery/vein Dice on the prespecified development
validation split. Secondary endpoints: FIVES vessel Dice, artery and vein
Dice, type accuracy, A/V ratio log error, Brier score, parameter count, and
wall clock time.

Before looking at any candidate score, the candidate is considered promising
only if its three seed mean improves the baseline by at least 0.03 absolute
mean A/V Dice **or** 0.15 relative thin vessel recall, while precision falls
by no more than 0.01. If no candidate reaches this threshold, the branch is
reported as negative or inconclusive and no additional tuning is allowed.

After all seeds are complete, one candidate may be frozen for a single
post hoc replay on Fundus AVSeg. That replay cannot be called independent
external validation and cannot change the candidate selection.

## Integrity boundaries

The supervisor manages only PIDs it starts. It never reads CIMT fixed test
files, official FIVES test labels, Fundus AVSeg labels, or mBRSET outcomes.
Logs, split files, hashes, and failed runs are retained; no failed branch is
deleted or repeatedly tuned.
